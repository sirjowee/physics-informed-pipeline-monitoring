# Physics-Informed Pipeline Monitoring — Reference Re-implementation

This repository is a reference re-implementation of the methods published in:

Adegboye, Komolafe & Joseph, "Physics-Aware ML Models for Pipeline Leak Detection and Quantification," IJSRED 7(6), 2024.
Adegboye, Komolafe & Joseph, "Electromagnetic Signal Classification Using Deep Learning for Pipeline Structural Health Monitoring," IJSRED 7(6), 2024.

The original development repository is no longer available. This code was written from scratch by Ibrahim M. Joseph (third author on both papers) beginning October 26, 2026, to reproduce the published experiments. All results here are on synthetic/simulated data, as in the papers. Reproduced results are reported in RESULTS.md alongside the published figures, including where they differ.

**Author:** Ibrahim Mohammed Joseph (IEEE Member) — josephibrahi@gmail.com

## Papers

1. **Leak detection.** Adegboye, Komolafe & Joseph, "Physics-Aware ML Models for Pipeline Leak Detection and Quantification," *IJSRED* 7(6), Nov–Dec 2024, pp. 1311–1316. https://www.ijsred.com/volume7/issue6/IJSRED-V7I6P142.pdf
   A physics-informed neural network (PINN) for leak detection, localization and rate quantification in multiphase pipelines, compared with a black-box neural network and a Real-Time Transient Model (RTTM) baseline.
2. **SHM classification.** Adegboye, Komolafe, Joseph & Kajero, "Electromagnetic Signal Classification Using Deep Learning for Pipeline Structural Health Monitoring," *IJSRED* 7(6), Nov–Dec 2024, pp. 1317–1322. https://www.ijsred.com/volume7/issue6/IJSRED-V7I6P143.pdf
   A one-dimensional convolutional network classifying four pipeline conditions (normal, crack, corrosion, leak) from simulated |S11| reflection traces, with Gaussian-noise robustness tests.

## Status

See [RESULTS.md](RESULTS.md). It holds the published numbers side by side with the numbers this code produces, every parameter the papers do not specify together with the value chosen here, and dated reproduction notes. Where a reproduced number is worse than the published one, RESULTS.md says so and gives the likely cause. Nothing in this repository is a claim about field or laboratory data.

## Layout

```
src/pipeline_monitoring/
  leak_detection/        two-fluid synthetic data generator, PINN, black-box and RTTM baselines
  shm_classification/    |S11| trace simulator, 1D-CNN, noise-robustness evaluation
scripts/                 command-line entry points (one per phase; see scripts/README.md)
tests/                   pytest suite: shapes, determinism, physics-residual sanity, loss decrease
figures/<paper>/         PNG figures regenerated by the evaluation scripts
```

## How to reproduce

Tested with Python 3.12.9, TensorFlow 2.18.1 (CPU), NumPy 2.0.2, SciPy 1.18.1, scikit-learn 1.9.1, matplotlib 3.11.2 on an Apple M1 (8 cores, macOS 15). All seeds default to 0.

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt && pip install -e .
ruff check . && pytest            # 28 tests, about 1 min
make reproduce                    # = python scripts/reproduce_all.py
```

`make reproduce` regenerates both datasets, trains every model, evaluates once on the held-out test sets, rewrites `results/*.json` and `figures/*/final_*.png`, and prints the RESULTS.md tables. It took **2.0 minutes** end to end on the machine above (SHM data 0.6 s, SHM train + eval 7 s, leak data 6 s, leak training of four networks + selection 95 s, leak evaluation 10 s). `make reproduce-full` uses 720 leak scenarios and 8000 training steps per network (not timed; expect roughly 5 minutes).

Individual steps, in order:

```bash
python scripts/shm_generate_data.py          # data/shm/s11_dataset.npz + example figure
python scripts/shm_train_eval.py             # results/shm_metrics.json, confusion matrices, curves
python scripts/leak_generate_data.py         # data/leak/leak_dataset.npz + sensor figure (--full for 720 scenarios)
python scripts/leak_train.py                 # lambda_phys sweep on validation, RTTM threshold, weights
python scripts/leak_evaluate.py              # results/leak_metrics.json + four figures
```

Reproducibility: the SHM pipeline, the leak data generator, the black-box network and the RTTM reproduce bit-for-bit from the seed. Training the PINN with the physics term does **not** reproduce bit-for-bit on this machine (see RESULTS.md §1.4, λ_phys row); the committed weights in `results/leak_models/` are the run reported, and evaluating them is deterministic.

## Ground rules

- No fabricated provenance: every commit is new work dated when it was made.
- No tuning toward the published numbers: hyperparameters are chosen on the validation set and the test set is reported once.
- Every parameter the papers leave unspecified is recorded in RESULTS.md with a one-line rationale, in the same change as the code that uses it.
